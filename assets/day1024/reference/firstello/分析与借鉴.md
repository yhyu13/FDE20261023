# Firstello 分析与借鉴 · AI 营销平台参考

> 对象：https://www.firstello.io/ （抓取 2026-10-24，原文快照见同目录 `page-snapshot-20261024.md`）
> 对照需求：`assets/real_request.md`（会议纪要文字版，权威）＋ `assets/day1024_c5_v1_v2/prompt1–3.md`（既有任务书，申沃内容运营线）
> 结论一句话：**Firstello 和我们是同一个域（AI 驱动营销），它在"执行层"——一句话→结构化条件→排序候选→个性化触达→星图闭环；而 real_request 要的是"策略层"——亮点提炼＋竞品分析＋区域化方案＋一线生成/负责人校正。它的四个交互机制可直接搬，但它给不了策略生成和人工校正，后者恰好是我们 day1024 工作台已有的架构。**

---

## 一、它是什么

AI 创业公司的自动外联助手（Autopilot outreach for AI startups），内测候补阶段，无公开产品。整站是一个 waitlist 落地页，**页内用活的组件演示产品**：条件解析、候选列表、表单填写、邮件草稿、星图，全部 mock 数据驱动。

> Meta 观察：它本身就是"单页 HTML + mock 数据讲产品故事"的产物——和我们 day1024 的做法同构，这条路线是 AI 创业圈通行做法。

## 二、产品功能四步闭环

| 步 | 它做什么 | 关键细节 |
|---|---|---|
| 1 定义与寻找 | 一句话 brief → 结构化查找条件 → 候选人列表 | ①②③ 三步**同屏**展示转换过程；条件是显式字段（title/industry/employees/region/**signal**）；候选按匹配度排序（96%/93%/91%）；**"标明仍需核实的条件"**——未核实的单独标出 |
| 2 填表与发信 | 自动访问对方官网填联系表单 + 以你的口吻写个性化邮件 | 双渠道 tab，各自按**渠道真实形态**渲染（表单就像表单、邮件就像邮件）；正文引用 signal（"看到你们在扩招客服"）；状态带时区（"已发送 · 周二 09:12（对方时区）✓ 已打开"）；Autopilot 全自动 |
| 3 星图 | 所有触达与回复汇成交互星空 | 谁打开/谁回复/谁约会议一眼看清；hover 探索、点击星星看详情（类别/名字/描述/渠道/时间）；图例三分：你/已触达/已回复 |
| 4 候补 | 留邮箱 + 一句话需求 | **分批开放（waves）**；登记后"你的星星已点亮" |

## 三、风格拆解

1. **贯穿始终的隐喻系统**：起飞 → 云层之上 → 发出信号 → 星座连线 → 留下你的位置。同一隐喻从文案、章节、交互贯穿到情感落点（"每一次回复都点亮一颗星"）。
2. **滚动即时间**：页面顶部 07:00 时间指示器，从清晨飞到星夜。
3. **编辑风排版**：短句大标题 + 斜体强调；章节编号（02–05）；中英双语一键切换。
4. **状态即信息**：每对象带紧凑状态行——动词完成时 + 时间 + 时区 + 渠道 + 同步去向。
5. **演示内嵌于叙事**：产品 UI 部件长在营销页里，页面自己讲产品故事，没有一张截图、一条功能列表。

## 四、我们的需求（real_request.md 还原）

1. **核心**：用 AI 为自己的产品（如 AI 平台）制定**完整营销解决方案**，提升知名度与销售业绩；要提炼产品亮点、结合**竞品分析**，形成**可落地的推广策略**——明确"而非简单的信息检索或收集工具"。
2. **路径**：**试点先行**（国内或海外单一市场，如宁波、墨西哥，验证后推广）；**区域化策略**（上海 vs 拉美特点不同）；**自下而上优化**（一线销售如 4S 店员工用 AI 生成初步方案 → 负责人校正优化 → 闭环）。
3. **待办**：定试点市场范围；客户安排销售负责人与 AI 团队交流当地市场情况。

## 五、Firstello 如何靠近我们的需求（逐条映射）

| real_request 需求点 | Firstello 对应机制 | 贴近度 | 判断 |
|---|---|---|---|
| 提炼产品亮点 | 无——它假设你已有 pitch，只管"把介绍送到对的人面前" | ✕ | **它不做策略输入端**。亮点提炼要从产品资料→可宣传卖点，这步我们 day1024 c5 的资料标注/口径资产架构可直接迁移 |
| 竞品分析 | 无 | ✕ | 它的"匹配"是**客户匹配**不是竞品匹配，完全没有竞品维度 |
| 区域化策略（宁波/墨西哥/上海/拉美） | region 是结构化筛选字段；signal 字段捕捉当地信号；发送按对方时区 | ◐ | region 在它那里只是过滤参数，不是策略生成器。但"**每个市场一张结构化条件卡（区域/规模/客群/当地信号）**"的思路可迁移：区域化策略的第一步就是把各市场差异结构化 |
| 一线销售生成初稿 + 负责人校正闭环 | 无——Autopilot 全自动，零人工环节 | ✕（反向印证） | 它的"全自动"恰好是客户**不要**的。客户要 human-in-the-loop；"销售生成→负责人校正"与 c5 工作台"销售提报→品牌起草→双审→DRI 放行"同构，我们领先 |
| 试点先行、验证后推广 | waitlist 分批开放（waves） | ◐（形式相似） | 它分批开放产品，客户分批验证市场。"单市场跑通→反馈→复制下一市场"的节奏，可用星图叙事呈现（点亮一颗星→连成星座） |
| 提升知名度与销售业绩（要看得见效果） | 打开→回复→约会议的漏斗 + 星图可视化 | ◐ | "策略效果可看见"的呈现方式值得学；红线：指标必须标样例数据，不写百分比 |

### 综合判断

**它靠近我们需求的方式是"执行层的自动化与可视化"，而需求的重心在"策略层的生成与人工闭环"。** 两者的真实交集有四个，全部是**交互机制**而非业务能力：

1. **一句话 → 结构化条件 → 排序候选**（三步同屏）——可用于"市场/客群/竞品"的结构化筛选与优先级排序；
2. **signal 个性化**——区域化方案的本地化依据：一线生成内容时嵌入当地市场信号；
3. **星图**——试点→反馈→复制的可视化叙事；
4. **渠道形态级渲染**——方案落到各渠道时按该渠道真实形态预览。

## 六、day1024 现有资产的迁移价值（桥接两份需求）

| real_request 要的 | c5 工作台（申沃线）已有的 | 迁移判断 |
|---|---|---|
| 一线销售 AI 生成 + 负责人校正闭环 | 五工作台 + 双审 + 版本失效 + DRI 放行 | **架构同构，直接复用**。"自下而上优化"就是角色工作台的故事换了个说法 |
| 提炼产品亮点（有据、可复用） | 资料归集→标注→口径资产（S/N 编号、来源分级、低置信确认台） | 作为策略生成的**证据底座**迁移 |
| 竞品分析 | 无 | **需新建**：竞品条目 + 维度对比 + 来源分级，形态与资料库同构 |
| 区域化策略 | 无（客群只有公交/海外/伙伴三分） | **需新建**：市场条件卡（区域/规模/渠道/当地信号/阶段），形态借 Firstello 的条件块 |
| 试点效果回流 | 反馈回流（FB→NEXT） | 直接复用 |

> ⚠️ **呈现警告**：real_request 明确说"而非简单的信息检索或收集工具"。c5 工作台的前半段（归集+标注）恰是这类面目。对这位客户，演示**必须以策略生成/区域方案/一线闭环开场**，归集标注只作为底下的证据层出现，不能当主角。

## 七、明确不借鉴的（红线对照）

1. **不学 96%/93% 匹配度话术**：无依据营销数字。展示排序分只能是可复现规则分 + "样例数据"标注（红线 3）。
2. **不学 Autopilot 全自动**：客户要的就是"AI 生成 + 负责人校正"，人工环节是需求本身，不是缺陷（红线 2 同向）。
3. **不学业务定位**：它是 outbound 找新客的执行工具；我们是策略生成 + 内部协作 + 试点验证，产出物要经负责人确认。

## 八、落地清单（按性价比排序）

1. **策略生成开场**：demo 首屏改为"一句话市场目标 → 结构化市场条件卡（区域/客群/竞品/当地信号）→ 按优先级排序的候选策略/市场列表"三步同屏（机制照搬 Firstello 第 1 步，对象从"客户"换成"市场/竞品/渠道"）。
2. **一线生成/负责人校正闭环打样**：复用 c5 五工作台架构，演示"4S 店销售生成区域初稿 → 负责人校正 → 定稿"的最短路径。
3. **竞品分析模块**（新建）：竞品卡 + 维度对比 + 来源分级，沿用资料库形态。
4. **试点星图**：市场/竞品/渠道画成星座，点亮 = 该试点验证通过，hover 看反馈摘要；作为汇报页情感落点。
5. **渠道形态级拟真复查**：公众号稿像公众号、官网像 CMS 预览、展会像一页纸、销售材料像 talk track。
6. **状态行统一**："动作完成时 · 时间 · 操作者 · 下一步归属"一行式。
7. **双语开关**（仅对外演示场景）。
