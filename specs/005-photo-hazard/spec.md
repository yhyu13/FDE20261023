## Requirements *(mandatory)*

### Functional Requirements

> 每条 FR 来自一条 **L3 机制**，并注明它属于哪个 L2 缺口。
> 凡是**要签字的数字与参数**，FR 必须写明溯源要求；
> 凡是**低置信结果**，FR 必须写明人工确认要求。

- **FR-001**: System MUST pHash 汉明距离去重并保留最清晰一张；Laplacian 方差 + 亮度分布筛废片（归"待清理"，不直接删）；EXIF 抽时间 / GPS / 设备
  - 来源：L2 L2-1 / L3 照片资产化管线（去重 → 废片 → EXIF → 归集）
  - 同族复用：与行业无关：巡检、仓储、零售、工地质检、文物普查通用
- **FR-002**: System MUST Objects（Project → Site → Borehole/ExplorationPoint → Process → Photo → Shot）→ Links（照片 ↔ 勘探点 ↔ 工序 ↔ 隐患类别 ↔ 记录）→ Actions+Write-back（挂载 / 标记 / 整改回写）
  - 来源：L2 L2-1 / L3 项目—勘探点—工序对象链（Ontology 三步法）
  - 同族复用：通用"影像资产对象化"模型：设备履历影像、检测批次影像、案件现场照
- **FR-003**: System MUST 勘探点/测试点/观测点统一编号模式与主数据；同一场地内重复编号直接告警（按同类标准"编号不得重复"）
  - 来源：L2 L2-1 / L3 勘探点编号主数据 + 唯一性校验
  - 同族复用：通用"编号唯一性"做法：设备位号、批次号、单据号、车辆牌号
- **FR-004**: System MUST 文字检测 + 识别；透视与反光预处理；输出文本 + bbox + 置信度；对孔号做格式校验 + 与点位台账映射，映射不到挂"待归集"
  - 来源：L2 L2-2 / L3 孔号 / 标牌 / 岩芯照片 OCR 管线
  - 同族复用：设备铭牌、资产标签、集装箱铅封、仓储货位编号通用
- **FR-005**: System MUST 按归档口径逐条核：① 像素尺寸 ≥ 2500×2000 且未剪辑；② 是否带钻孔编号；③ 是否带标尺或参照物；④ 编号是否在点位台账里。不合规 → 进不了归档链，只能回现场补拍
  - 来源：L2 L2-2 / L3 照片合规前置检查（可机械判定）
  - 同族复用：任何"原始证据/影像归档"场景：试验影像、检测影像、验收影像
- **FR-006**: System MUST OCR 文本、隐患标签、时间、项目 / 勘探点 / 工序全部同索引；向量召回与结构化过滤可叠加
  - 来源：L2 L2-2 / L3 OCR 文本入索引 + 混合检索
  - 同族复用：通用"把图里的字变成可检索字段"：票据、图纸、公示栏
- **FR-007**: System MUST 依据甲方现行安全检查表 + 自然资源领域判定条目，一条判定标准一次专项提问（"这张图里钻探机台配电是否实现一机一闸一漏电？""作业人员是否按要求佩戴安全帽并穿戴反光背心？""道路内作业是否设置了明显安全警示标识？"），输出 JSON {条目号, 是否存在, 置信度, 描述, bbox}
  - 来源：L2 L2-3 / L3 按判定条目逐类提问的 VLM 范式
  - 同族复用：任何"有既定检查项体系"的场景：EHS 检查、ISO 内审、设备点检、监理旁站
- **FR-008**: System MUST 每条判定条目配：① 判据（一句话，说清"什么算隐患"）；② 看图要点（该看画面哪个位置）；③ 依据出处（条目号 + 原文）；④ 1–2 张正例/反例图。新人按卡片自查，老手按卡片复核
  - 来源：L2 L2-3 / L3 新人判据卡（把老手的"看"变成可交接的规则）
  - 同族复用：通用"隐性经验显性化"：老师傅工艺判据、老中医经验方、质检眼力、带徒教材
- **FR-009**: System MUST 隐患类别 → 风险等级 → 整改要求，分级口径来自甲方既有制度，不由模型定级；用甲方真实照片人工标注建集，按条目分别出召回 / 精确率与混淆样本图
  - 来源：L2 L2-3 / L3 风险分级映射表 + 评测集（分条目出指标）
  - 同族复用：所有"小样本视觉任务"的通用评测范式
- **FR-010**: System MUST Photo → DetectedHazard → Nonconformity → Rectification → RecheckPhoto；每步带责任人、期限、状态
  - 来源：L2 L2-4 / L3 不符合项对象链与闭环台账
  - 同族复用：质量 / 安全 / 合规类问题闭环通用
- **FR-011**: System MUST 同一不符合项的隐患照与复查照并排（部位 / 时间 / 说明）；导出安全台账与归档索引（编号、类别、等级、责任人、期限、状态、照片索引）
  - 来源：L2 L2-4 / L3 前后对照视图 + 归档台账导出
  - 同族复用：复查比对、索赔取证、创优工程资料归档通用
- **FR-012**: System MUST 归档链自带"原始件只读副本 + 校验哈希 + 异地/云备份位"，导出时提示"硬盘未做防震/防水/防尘"这条行业风险
  - 来源：L2 L2-4 / L3 外业数据备份与介质防护提醒
  - 同族复用：通用"原始数据保全"：测绘原始数据、试验原始数据、影像原始文件
- **FR-013**: System MUST 置信度分档；确认 / 否认；否认样本回流成 few-shot 与评测集；不自动开整改通知
  - 来源：横贯 / L3 人工复核队列 + 否认样本回流
  - 同族复用：任何 CV 落地都要用的置信度管理范式
- **FR-014**: System MUST 模型只能引用甲方检查表与适用判定条目；不得引用公开通用经验库或公开数据集冒充现场依据；对外输出必须写明所依据的条目号
  - 来源：横贯 / L3 引用白名单与范围声明
  - 同族复用：审计与合规场景的通用"来源可追"约束

## Success Criteria *(mandatory)*

### Measurable Outcomes

> 目标值来自题解的 OKR。**基线为 `Day1 实测` 的条目，在实测前不构成承诺。**
> 没有权威测评的指标一律标「我方验收目标（非业界实测）」。

- **SC-001**: 隐患线索召回率 → 目标 ≥ 80%（在 ≥ 200 张甲方真实照片上，按条目分别统计）（基线：0；怎么量：评测集跑分脚本，随代码入库）　**北极星**
- **SC-002**: 隐患精确率 → 目标 ≥ 70%（同评测集）（基线：0；怎么量：同上；与 KR1 成对看，只看召回会误判为成功）
- **SC-003**: 照片自动归集归档率 → 目标 ≥ 95%（抽 100 张，正确落到项目/勘探点/工序，无需人工改名）（基线：0；怎么量：人工抽检）
- **SC-004**: 自然语言速查响应时间 → 目标 ≤ 10 秒返回候选 Top-20（基线：人工翻找（分钟~小时级）；怎么量：端到端计时）
- **SC-005**: 孔号识别准确率（格式校验通过 + 台账可映射） → 目标 ≥ 90%（抽样 100 张）（基线：0；怎么量：抽检）
- **SC-006**: 照片合规前置检查覆盖 → 目标 ≥ 95% 的归档照片被自动核过 4 项规格（基线：0；怎么量：台账统计）
- **SC-007**: 误报率 → 目标 ≤ 15%（进入人工复核队列的比例）（基线：—；怎么量：确认队列统计）
- **SC-008**: 新人判据卡可用性 → 目标 ≥ 3 类隐患配齐判据卡；≥ 1 名新人用它独立说对 1 条依据（基线：0；怎么量：现场演示 + 记录）
- **SC-009**: 误报直接生成正式安全记录的数量 → 目标 = 0（未经人工确认不得进主表、不得自动开整改通知）（基线：—；怎么量：审计日志检查）　**护栏**

> 拆解计数核对：> L2-1 → 3 条，L2-2 → 3 条，L2-3 → 3 条，L2-4 → 3 条，横贯 → 2 条。L3 是 14 条机制，不是 14 个 L2。 L2 保持 4 条不变，这是深度控制。
