### User Story 1 - 照片只是文件，没有对象 (Priority: P1)

**业务问题**：上百张现场照片，隐患藏在哪一张？

**根因**：没有"项目 → 部位 → 工序 → 照片"的对象链；EXIF 只躺在本地文件里，导入后无法归集；文件名无语义

**为什么值得做**：照片只有挂到对象上，才谈得上"按项目 / 部位 / 工序找"；这也是山南"成果反演、反敷"所需影像底座的起点

### User Story 4 - 隐患类别与风险分级没有权威口径 (Priority: P4)

## Requirements *(mandatory)*

### Functional Requirements

> 每条 FR 来自一条 **L3 机制**，并注明它属于哪个 L2 缺口。
> 凡是**要签字的数字与参数**，FR 必须写明溯源要求；
> 凡是**低置信结果**，FR 必须写明人工确认要求。

- **FR-001**: System MUST pHash 汉明距离去重并保留最清晰一张；Laplacian 方差 + 亮度分布筛废片（归"待清理"，不直接删）；EXIF 抽时间 / GPS / 设备
  - 来源：L2 L2-1 / L3 照片资产化管线（去重 → 废片 → EXIF → 归集）
  - 同族复用：与行业无关：巡检、仓储、零售、工地质检、文物普查通用
- **FR-002**: System MUST Objects（Project → Section/Part → Process → Photo → Shot）→ Links（照片 ↔ 部位 ↔ 工序 ↔ 隐患类别）→ Actions+Write-back（挂载 / 标记 / 整改回写）
  - 来源：L2 L2-1 / L3 项目—部位—工序对象链（Ontology 三步法）
  - 同族复用：通用"影像资产对象化"模型：设备履历影像、检测批次影像、案件现场照
- **FR-003**: System MUST 归集后按规范重命名，并把部位 / 工序 / 时间写回 EXIF；照片脱离本平台也能被检索；侧写失败有降级路径
  - 来源：L2 L2-1 / L3 自动命名与元数据侧写
  - 同族复用：通用"文件即数据"做法：报告、图纸、录音的元数据治理
- **FR-004**: System MUST 文字检测 + 识别；对透视与反光做预处理；输出文本 + bbox + 置信度；对关键字段（编号、日期）做格式校验
  - 来源：L2 L2-2 / L3 标牌 / 铭牌 / 验收牌 OCR 管线
  - 同族复用：设备铭牌、资产标签、集装箱铅封、仓储货位编号通用
- **FR-005**: System MUST 钻孔编号、标高点号、管位牌、样品编号 → 统一编号模式 + 正则校验 + 与点位 / 样品台账映射；映射不到则挂"待归集"
  - 来源：L2 L2-2 / L3 工程编号规范化与主数据映射
  - 同族复用：设备位号、批次号、单据号、车辆牌号的通用做法
- **FR-006**: System MUST OCR 文本、隐患标签、时间、项目 / 部位全部同索引；向量召回与结构化过滤可叠加
  - 来源：L2 L2-2 / L3 OCR 文本入索引 + 混合检索
  - 同族复用：通用"把图里的字变成可检索字段"：票据、图纸、公示栏
- **FR-007**: System MUST Photo → DetectedHazard → Nonconformity → Rectification → RecheckPhoto；每步带责任人、期限、状态
  - 来源：L2 L2-3 / L3 不符合项对象链与闭环台账
  - 同族复用：质量 / 安全 / 合规类问题闭环通用
- **FR-008**: System MUST 同一不符合项的隐患照与复查照并排（部位 / 时间 / 说明）；导出安全台账（编号、类别、等级、责任人、期限、状态、照片索引）
  - 来源：L2 L2-3 / L3 前后对照视图与整改台账导出
  - 同族复用：复查比对、索赔取证、创优工程资料归档通用
- **FR-009**: System MUST 依据《房屋市政工程生产安全重大事故隐患判定标准（2022 版）》判定条目 + 甲方现行安全检查表，一条判定标准一次专项提问（"这张图里基坑临边防护是否连续完整且符合该条判定要求？"），输出 JSON {条目号, 是否存在, 置信度, 描述, bbox}
  - 来源：L2 L2-4 / L3 按国标条目逐类判断的 VLM 提问范式
  - 同族复用：任何"有既定检查项体系"的场景：EHS 检查、ISO 内审、设备点检、监理旁站
- **FR-010**: System MUST 隐患类别 → 风险等级 → 整改要求；分级口径来自甲方既有制度与国标，不由模型定级
  - 来源：L2 L2-4 / L3 风险分级映射表
  - 同族复用：通用"分类 → 等级 → 处置动作"映射：缺陷分级、投诉分级、缺陷优先级
- **FR-011**: System MUST 用甲方真实照片人工标注建集；按条目分别出召回 / 精确率与混淆样本图；检索命中率与检测指标分开看
  - 来源：L2 L2-4 / L3 评测集与分条目指标
  - 同族复用：所有"小样本视觉任务"的通用评测范式
- **FR-012**: System MUST 置信度分档；确认 / 否认；否认样本回流成 few-shot 与评测集；不自动开整改通知
  - 来源：横贯 / L3 人工复核队列 + 否认样本回流
  - 同族复用：任何 CV 落地都要用的置信度管理范式
- **FR-013**: System MUST 模型只能引用国标判定条目与甲方台账；不得引用公开通用经验库或公开数据集冒充现场依据；对外输出必须写明所依据的条目号
  - 来源：横贯 / L3 引用白名单与范围声明
  - 同族复用：审计与合规场景的通用"来源可追"约束

## Success Criteria *(mandatory)*

### Measurable Outcomes

> 目标值来自题解的 OKR。**基线为 `Day1 实测` 的条目，在实测前不构成承诺。**
> 没有权威测评的指标一律标「我方验收目标（非业界实测）」。

- **SC-001**: 隐患线索召回率（自建标注评测集，按判定条目分层统计） → 目标 ≥ 80%（我们设定的验收目标，非业界实测）（基线：Day1 实测（需甲方真实照片自建标注集）；怎么量：评测脚本随代码入库）　**北极星**
- **SC-002**: 隐患识别精确率 → 目标 ≥ 70%（我们设定的验收目标，非业界实测）（基线：Day1 实测；怎么量：同上；与 KR1 必须成对看）
- **SC-003**: 照片自动归集归档率 → 目标 ≥ 95%（抽 100 张，正确落到项目 / 部位 / 日期，无需人工改名）（基线：0；怎么量：人工抽检）
- **SC-004**: 自然语言速查响应时间 → 目标 ≤ 10 秒返回候选 Top-20（基线：人工翻找（分钟~小时级）；怎么量：端到端计时）
- **SC-005**: 误报率（进入人工复核队列的比例） → 目标 ≤ 15%（基线：—；怎么量：确认队列统计）
- **SC-006**: OCR 关键字段准确率（编号 / 日期类） → 目标 ≥ 85%（抽样 100 个）（基线：—；怎么量：抽检）
- **SC-007**: 未经人工确认即进入正式安全记录 / 整改通知的条数 → 目标 = 0（基线：0；怎么量：复核队列操作日志 + 正式台账反查）　**护栏**

> 拆解计数核对：> L2-1 → 3 条，L2-2 → 3 条，L2-3 → 2 条，L2-4 → 3 条，横贯 → 2 条。L3 是 13 条机制，不是 13 个 L2。 L2 保持 4 条不变，这是深度控制。
