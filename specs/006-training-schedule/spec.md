### User Story 1 - "谁该训"没有可执行、且可分层的判定口径 (Priority: P1)

**业务问题**：上千名护士，这次培训到底该安排谁？

**根因**：规则来自三类互不相同的权威来源——人社局职业技能等级认定目录（证书种类与有效期）、卫健口径、《新入职护士培训大纲（试行）》（主要适用三级综合医院）；而服务的医院口径不统一（三级综合 / 二级 / 民营），同一套清单不能直接套全部机构；这些规则还散在制度文件与口述里，各院 Excel 各写各的

**为什么值得做**：这是整个系统的地基，也是"分层抽选"里"分层"的真实含义。基底错，后面覆盖率再高也是错的名单；医院第一个质疑的一定是"这个人为什么该训"

**Independent Test**: ⚠️ 待补——写清「怎么单独验收这一条」，以及「只实现这一条时交付什么」。

**Acceptance Scenarios**: ⚠️ 待补——Day1 现场按真实业务动作补 Given/When/Then。

### User Story 2 - 硬约束只存在于人的判断里，机器给不出零违反保证 (Priority: P2)

**业务问题**：上千名护士，这次培训到底该安排谁？

**根因**：证书有效期、先修、岗位职称匹配、班次冲突、名额、医院配额、排班滞后，全部靠翻表和记忆；改一轮名单崩一轮

**为什么值得做**：名单里出现一个证书过期的人，医院会整个退回。本题的商业价值不在"更快"，在"绝对不出错"

**Independent Test**: ⚠️ 待补——写清「怎么单独验收这一条」，以及「只实现这一条时交付什么」。

### User Story 3 - 名单不可解释、不可干预 (Priority: P3)

**业务问题**：上千名护士，这次培训到底该安排谁？

**根因**：选派说不出"为什么是他"，未入选说不出"为什么不是他"；医院一句"换人"就得从头重排

**为什么值得做**：直接对应业务目标里的"名单确认"——没有解释与可干预接口，医院不会签这个名单

**Independent Test**: ⚠️ 待补——写清「怎么单独验收这一条」，以及「只实现这一条时交付什么」。

### User Story 4 - 跨月资源冲突与分层公平不在同一个模型里 (Priority: P4)

**业务问题**：上千名护士，这次培训到底该安排谁？

**根因**：只看单月，讲师 / 场地 / 时段冲突月底爆发；同一批人反复被排；三级综合与民营医院的公平与容量口径也不同

**为什么值得做**：直接对应业务目标里的"跨月排课"；单月排得下不等于这个季度排得下

### User Story 5 - 名单没有正式依据的版本与留痕，执行效果也不回流 (Priority: P5)

**业务问题**：上千名护士，这次培训到底该安排谁？

**根因**：名单是给医院与卫健看的正式依据，现在只是一份 Excel；谁在何时基于哪版规则改的、依据是什么事后说不清；排了没来的数据也回不来

**为什么值得做**：国有背景 + 评价机构备案身份，决定留痕与可审计是硬门槛；确认后若被推翻、责任不清，流程会卡死

**Independent Test**: ⚠️ 待补——写清「怎么单独验收这一条」，以及「只实现这一条时交付什么」。

## Requirements *(mandatory)*

### Functional Requirements

> 每条 FR 来自一条 **L3 机制**，并注明它属于哪个 L2 缺口。
> 凡是**要签字的数字与参数**，FR 必须写明溯源要求；
> 凡是**低置信结果**，FR 必须写明人工确认要求。

- **FR-001**: System MUST 规则分三层锚定：人社技能等级目录（证书种类/有效期）→ 卫健口径 → 《新入职护士培训大纲（试行）》；再按机构分类（三级综合 / 二级 / 民营）切成"通用层 + 机构层"，机构层只写差异
  - 来源：L2 L2-1 / L3 官方口径锚定 + 机构分类分层规则集
  - 同族复用：任何"同一制度、不同主体适用口径不同"的场景：不同规模企业的内控要求、医院等级分层诊疗、政务事项分层受理
- **FR-002**: System MUST LLM 从制度文件、卫健口径与访谈记录中抽取候选规则 + 出处片段 → 逐条由运营 / 医院确认；LLM 只抽规则，不出名单
  - 来源：L2 L2-1 / L3 LLM 规则抽取 + 人工确认台
  - 同族复用：规则散在文件与口述里的场景：质检判定标准、准入审核条件、报销规则、审计取样口径
- **FR-003**: System MUST 按分层口径独立枚举"应训人员全集"，逐个给出落选原因；额外输出"应训但谁都没排上"的缺口清单
  - 来源：L2 L2-1 / L3 应训全集枚举 + 缺口清单
  - 同族复用：需求预测、排班缺岗盘点、合规检查覆盖率盘点、补贴资格人群摸底
- **FR-004**: System MUST 规则用可读表格 / DSL 表达，带版本、生效日期、来源出处、owner；硬约束与软目标权重分离；业务改规则不发版
  - 来源：L2 L2-2 / L3 可执行规则集（配置化 DSL）
  - 同族复用：排班准入、审计取样规则、资质审核、授信评分卡、安全作业许可
- **FR-005**: System MUST 变量 = 人 × 期次是否分配；硬约束 = 证书有效期 / 先修 / 岗位职称 / 班次 / 容量 / 医院配额；目标 = 最大化加权得分；LLM 不参与决策；不可行时输出缺多少容量、卡在哪条约束、放开哪条能解
  - 来源：L2 L2-2 / L3 CP-SAT 约束建模（零违反 + 不可行诊断）
  - 同族复用：排班、车辆调度、产能分配、值班编排、机房与设备资源分配
- **FR-006**: System MUST 求解器之外再写一个只读断言器，逐条断言已排名单的合法性；任何一条违反即拒绝出名单，断言结果随名单留档
  - 来源：L2 L2-2 / L3 硬约束断言器（独立复核）
  - 同族复用：任何"错了就要退回"的交付物：结算单、放行单、资质名单、合规报送
- **FR-007**: System MUST 每条选派输出：命中的硬规则、软目标得分分解、竞争者与差距；未入选者输出落选原因（证书将过期 / 不在本次范围 / 名额已满）
  - 来源：L2 L2-3 / L3 可解释层（选他 / 不选他）
  - 同族复用：招生录取解释、授信审批理由、招聘推荐说明、供应商入围理由
- **FR-008**: System MUST 锁定 / 替换 / 排除写入固定解，求解器带固定解重算其余部分；干预动作本身留痕
  - 来源：L2 L2-3 / L3 人工干预 + 增量重排
  - 同族复用：排班改单、产能临时调整、售后改派、审批退回改件
- **FR-009**: System MUST 期次容量 / 讲师 / 场地 / 时段做成资源池，跨月统一排并检测冲突；上期已训者降权，保证轮转
  - 来源：L2 L2-4 / L3 跨月资源池 + 轮转降权
  - 同族复用：会议排期、设备维保排程、多班次轮岗、跨期项目排产
- **FR-010**: System MUST 按机构类别 / 医院 / 科室 / 职称分层输出名额与实际落位对照：分布极差、最久未训优先命中率、每层配额达成率
  - 来源：L2 L2-4 / L3 分层公平性度量
  - 同族复用：配额分配评审、资源分配公平性公示、指标下达与对账
- **FR-011**: System MUST 初稿 → 医院确认（意见与修改留痕）→ 冻结为不可变快照（规则版本 + 求解结果 + 解释全绑定）→ 通知 / 导出；改动必须新版本
  - 来源：L2 L2-5 / L3 确认流 + 版本冻结 + 操作留痕
  - 同族复用：审计取证、版本化报表、对外承诺文件、评标结果归档
- **FR-012**: System MUST 实际到场与考核结果回写，更新到场率权重 → 下一轮名单更准
  - 来源：L2 L2-5 / L3 执行回流与到场率校准
  - 同族复用：任何"分配了但不一定执行"的运营闭环：派单、维保工单、驻场服务

## Success Criteria *(mandatory)*

### Measurable Outcomes

> 目标值来自题解的 OKR。**基线为 `Day1 实测` 的条目，在实测前不构成承诺。**
> 没有权威测评的指标一律标「我方验收目标（非业界实测）」。

- **SC-001**: 本期应训覆盖率（被安排人数 / 应训人数，按分层口径） → 目标 ≥ 基线 + 20 个百分点（基线：Day1 实测（人工方案同口径）；怎么量：名单人数 ÷ 应训全集人数（全集由同一枚举器产出））　**北极星**
- **SC-002**: 出名单 + 排课端到端耗时（数据准备 → 名单可交付） → 目标 ≤ 2 小时（基线：Day1 实测（预估 2 人 × 1 天）；怎么量：端到端计时）
- **SC-003**: 名单可解释率（选派有理由、落选有原因） → 目标 100%（基线：0；怎么量：抽查 30 条 + 系统计数）
- **SC-004**: 医院主动改单率 → 目标 ≤ 20%（基线：—；怎么量：确认流记录）
- **SC-005**: 人工干预重排成功率 → 目标 100%，且不违反硬约束（基线：—；怎么量：现场演示 2 次干预）
- **SC-006**: 硬约束违反数（证书有效期 / 先修 / 岗位职称 / 班次 / 容量 / 配额） → 目标 = 0（零违反）（基线：人工方案偶有漏；怎么量：独立断言器报告 + 人工复核）　**护栏**
