### User Story 1 - 农事记录没有对象化，"标准"落不到现场动作上 (Priority: P1)

**业务问题**：蓝莓种植的每一步，能不能都有据可查？

**根因**：记录形态是"地块 + 日期 + 一句话"，没有品种/生育期/地块/行/株/农事批次/采收批次这些对象，标准条款挂不到具体动作上

**为什么值得做**：档案的唯一价值是"能不能证明这次操作符合规范"。不对象化，标准符合性、品质归因、认证举证三条线全部接不上

**Independent Test**: ⚠️ 待补——写清「怎么单独验收这一条」，以及「只实现这一条时交付什么」。

**Acceptance Scenarios**: ⚠️ 待补——Day1 现场按真实业务动作补 Given/When/Then。

### User Story 2 - 投入品是不可核的黑箱 (Priority: P2)

**业务问题**：蓝莓种植的每一步，能不能都有据可查？

**根因**：农药/肥料/水的信息只存在于包装标签照片里，登记证号、成分、剂量、禁限用属性没有落成可比对的字段

**为什么值得做**：禁限用与安全间隔期是红线；投入品不可核 = 抽检与认证必挂；也是 AI 模型的输入质量底线

**Independent Test**: ⚠️ 待补——写清「怎么单独验收这一条」，以及「只实现这一条时交付什么」。

### User Story 3 - 技术指导与培训交付过程没有留痕 (Priority: P3)

**业务问题**：蓝莓种植的每一步，能不能都有据可查？

**根因**：品种推荐、栽培方案、建园指导、田间学校授课是这家单位的"产品"，但交付给谁、给了什么、覆盖多少面积、结果如何，几乎没有记录

**为什么值得做**：这是推广方特有的缺口，也是本方案区别于"普通农场建档"的地方；没有它，档案只能覆盖自有基地，覆盖不了真正的服务半径

### User Story 4 - 农事与品质、成效指标不在同一时间轴上 (Priority: P4)

**业务问题**：蓝莓种植的每一步，能不能都有据可查？

**根因**：出现糖度、硬度、商品率波动时，无法定位到某次施氮、打药或灌溉；示范区的亩产/增产/辐射面积/培训人次也散在不同报表里

## Requirements *(mandatory)*

### Functional Requirements

> 每条 FR 来自一条 **L3 机制**，并注明它属于哪个 L2 缺口。
> 凡是**要签字的数字与参数**，FR 必须写明溯源要求；
> 凡是**低置信结果**，FR 必须写明人工确认要求。

- **FR-001**: System MUST Objects（Farm / Block / Row / Bush / Operation / Input / HarvestBatch / Quality / Clause）→ Links（Block→Row→Bush、Operation→Block·Bush、HarvestBatch→Operation+Quality、Clause→Operation）→ Actions+Write-back（确认即写入、作废即改）
  - 来源：L2 L2-1 / L3 农事本体（Ontology 三步法）
  - 同族复用：通用"种植/养护"对象模型；换行业只换实体名（设备/模具/批次/客户同一套结构）
- **FR-002**: System MUST 把《蓝莓栽培技术规范》拆成有对象、有触发条件、有判定依据的作业项（如"采前 N 天内不得使用某类药剂"），条款原文与判定口径一起入库
  - 来源：L2 L2-1 / L3 标准条款 → 可勾选作业项
  - 同族复用：任何"标准/规范/规程"落到现场的场景：施工工艺卡、检验规程、EHS 检查项、内审条款
- **FR-003**: System MUST 拍照或语音口述 → ASR+VLM 抽成草稿 → 农工只做"确认/改" → 低置信字段高亮 → 写入对象
  - 来源：L2 L2-1 / L3 确认式采集（拍照 + 一句话）
  - 同族复用：任何"现场零散输入"的场景：巡检打卡、仓储收货、实验记录、设备点检
- **FR-004**: System MUST 从包装/标签照读产品名、成分、登记证号、剂量 → 映射投入品主数据 → 登记证号与禁限用属性由人工补录确认
  - 来源：L2 L2-2 / L3 投入品主数据 + 包装标签 OCR 管线
  - 同族复用：任何"标签即主数据"的场景：建材质保书、危化品 SDS、兽药疫苗、试剂耗材
- **FR-005**: System MUST 规则来自官方清单与农艺师，模型不得臆造；录入即校验，不通过当场阻断并指出依据条款
  - 来源：L2 L2-2 / L3 合规规则引擎（禁限用 + 安全间隔期）
  - 同族复用：任何有硬性约束的场景（药、证、票、危化品、超期资质）
- **FR-006**: System MUST 每条投入品使用记录绑定对象 + 时间；采收批次反向展开"采前 N 天内的全部投入品"
  - 来源：L2 L2-2 / L3 投入品—采收批次关联台账
  - 同族复用：食品安全抽检溯源、农残速测异常溯源、追溯召回范围圈定
- **FR-007**: System MUST 每次指导登记：指导对象（合作社 / 农户 / 新基地）、方式（现场 / 电话 / 田间学校）、交付物（栽培方案 / 种苗建议 / 建园指导）、面积与株数、交付人
  - 来源：L2 L2-3 / L3 技术指导交付记录
  - 同族复用：技术服务型组织通用：设备维保商技术服务单、咨询公司顾问工单、检测机构委托单
- **FR-008**: System MUST 课次、学员名单与人数、教材版本、签到、考核结果
  - 来源：L2 L2-3 / L3 培训场次台账
  - 同族复用：企业内训、农机校/驾校、职业院校课程记录
- **FR-009**: System MUST 指导后按节点回访（成活率、产量、品质），复访结论回流修订方案与教材
  - 来源：L2 L2-3 / L3 指导闭环与复访回流
  - 同族复用：售后回访、慢病随访、农户随访、会员复购跟进
- **FR-010**: System MUST 农事、投入品、品质指标落在同一时间轴上，按株 / 行 / 批次查询
  - 来源：L2 L2-4 / L3 植株/批次级时序视图
  - 同族复用：通用"资产时序档案"：设备履历、批次质量谱、客户跟进史
- **FR-011**: System MUST 计算投入品暴露与品质指标的同期共现与相关性，输出"可能相关 + 样本量 + 区间"；文案统一写"提示 / 相关"
  - 来源：L2 L2-4 / L3 相关性归因提示（只提示不下结论）
  - 同族复用：通用"多因素同期共现"提示：工单与返修、巡检与故障、投放与转化
- **FR-012**: System MUST 示范区亩产/增产/辐射面积/培训人次/种苗销量统一口径入库，支持按品种、区域、年度对比
  - 来源：L2 L2-4 / L3 成效指标台账
  - 同族复用：项目后评价、示范区验收、推广成效统计、专项资金绩效报告
- **FR-013**: System MUST 每条记录带确认人与确认时间；未确认不计入统计；否认样本回流成 few-shot 与评测集；历史人工记录回测作为基线
  - 来源：横贯 / L3 确认闭环 + 闭环即评测
  - 同族复用：任何"AI 出草稿、人来定稿"的通用闭环（合同审核、质检判定、客服工单）

## Success Criteria *(mandatory)*

### Measurable Outcomes

> 目标值来自题解的 OKR。**基线为 `Day1 实测` 的条目，在实测前不构成承诺。**
> 没有权威测评的指标一律标「我方验收目标（非业界实测）」。

- **SC-001**: 追溯完整度：随机抽 1 个采收批次，能回溯到的关键农事占标准要求项的比例 → 目标 ≥ 90%（抽 3 个批次，缺项逐条列出）（基线：Day1 实测（现状 ≈ 0，纸质散记无法倒查）；怎么量：随机抽批次跑追溯导出，逐项打勾 + 出缺项清单）　**北极星**
- **SC-002**: 农事记录结构化率（字段正确且落到正确对象） → 目标 ≥ 85%（抽样 100 条人工核对）（基线：0；怎么量：抽样核对表）
- **SC-003**: 单条农事录入耗时 → 目标 ≤ 2 分钟（拍照 + 一句话）（基线：Day1 实测（预估 10–15 分钟填表）；怎么量：现场秒表，5 名农工各录 3 条取均值）
- **SC-004**: 标准符合性对照表可判定率（有作业记录可对照的条款占比） → 目标 ≥ 80%（基线：0；怎么量：对照表统计）
- **SC-005**: 投入品可核率（有登记证号与剂量、能参与合规校验的记录占比） → 目标 ≥ 95%（基线：Day1 实测；怎么量：字段完备度统计）
- **SC-006**: 追溯档案人工复核一次通过率 → 目标 ≥ 80%（导出后未被要求修改的份数）（基线：—；怎么量：复核记录）
- **SC-007**: 不合规投入品入库存量（禁用 / 超安全间隔期 / 超剂量） → 目标 = 0（基线：0；怎么量：阻断日志 + 对全量记录复跑合规校验，违规 0 条）　**护栏**

> 拆解计数核对：> L2-1 → 3 条，L2-2 → 3 条，L2-3 → 3 条，L2-4 → 3 条，横贯 → 1 条。L3 是 13 条机制，不是 13 个 L2。 L2 保持 4 条不变，这是深度控制。
