# Feature Specification: 申沃 AI 营销协作台 · 分角色闭环演示

**Feature Branch**: `007-marketing-role-workbenches`
**Created**: 2026-10-24
**Status**: Approved for implementation
**Input**: `assets/day1024_sol_v1_v2/prompt1.md`、`prompt2.md`；2026-10-24 用户批准六身份、双审核、DRI 放行及离线演示的独立验收口径。

**Scope correction**: 用户逐条核对企业任务1/2后，于本轮明确要求“go”：新增下面 US5/US6 的资料归集标注、场景关系识别闭环，不再以预置资料浏览与人工选编号冒充业务能力。

## User Scenarios & Testing

### User Story 1 - 每个人只处理自己的责任 (Priority: P1)

来源 L2-A：流程没有按职责分离；L3：身份到待办/操作白名单映射。同族复用：同一营销项目的官网、展会和销售物料审批。

**Independent Test**: 分别进入六种身份，每个首页标题、待办和主要操作不同；销售无法审批，DRI 无法替技术签字。

**Acceptance Scenarios**:
1. **FR-001** Given 未选择身份，When 选择 DRI/销售/内容/技术/项目/品牌之一，Then 进入相应首页且仅显示其工作导航；模拟登录边界始终可见。
2. **FR-002** Given 销售或 DRI 身份，When 尝试其他角色专属命令，Then 命令失败且业务状态不变。

### User Story 2 - 从客户问题到可信选题 (Priority: P1)

来源 L2-B：客户问题与事实资产没有可信关联；L3：CQ→选题→证据与成熟度映射。同族复用：公交、海外和行业伙伴的同类问题匹配。

**Independent Test**: 销售提交问题，DRI 纳入排期，内容选择四类渠道之一生成待审模板；证据缺失或使用权待确认时不得提交。

**Acceptance Scenarios**:
1. **FR-003** Given 销售提交客户问题，When DRI 纳入项目，Then 生成带问题编号、客群、周次和负责人角色的选题；重复纳入不重复生成。
2. **FR-004** Given 素材库，When 搜索/筛选/查看条目，Then 可见来源链接或原文件位置、时间、客群、成熟度、允许表达与禁用边界，含本地题目图片。
3. **FR-005** Given 内容身份，When 生成公众号/官网/展会/销售模板，Then 正文与内部备注分离且引用证据；无证据或有未确认项的选题提交被阻断，AI 输出明确为预置模板模拟。

### User Story 3 - 审核必须对当前版本负责 (Priority: P1)

来源 L2-C：口径修订、确认与流程责任混合；L3：版本绑定签字与确定性门禁。同族复用：同一事实在多渠道物料中的版本审批。

**Independent Test**: 内容提交→技术和项目分别签字→品牌确认→DRI 模拟放行；退回或修改后旧签字不可继续放行。

**Acceptance Scenarios**:
1. **FR-006** Given 待审核版本，When 技术/项目分别通过或退回，Then 只写自己的签字，双通过才进入品牌；退回进入修改态且有理由。
2. **FR-007** Given 已有审核或已放行稿件，When 内容修改并保存，Then 新版本递增，全部旧签字和放行失效；既有批准口径历史保持可追溯。
3. **FR-008** Given 当前稿件，When 品牌确认及 DRI 放行，Then 必须当前版本双审核、品牌确认、证据/图片使用状态齐备；完成后保存可复用口径与操作者审计记录。只模拟放行，不实际发布。

### User Story 4 - 决定可保存、可带走、可回流 (Priority: P1)

来源 L2-D：反馈与后续工作脱节；L3：结构化反馈回流、可审计导出。同族复用：下一轮同类内容排期。

**Independent Test**: 放行后销售录入模拟反馈，DRI 纳入下一轮；刷新保留业务状态，导出可读清单。

**Acceptance Scenarios**:
1. **FR-009** Given 模拟放行稿件，When 销售提交反馈且 DRI 接纳，Then 形成带原稿来源的新问题/下一轮待办，并去重；未放行稿件不能录入发布后反馈。
2. **FR-010** Given 已操作的项目，When 刷新或导出，Then 保留选题、版本、审核和日志；导出同时含模拟声明、来源、成熟度、版本及真实导出时间。存储不可用时显示会话模式警告，损坏数据不执行。
3. **FR-011** Given 单文件成品，When 断网打开并访问各角色，Then 无远端依赖、无控制台错误，图片内嵌，桌面/窄屏不溢出；所有业务数字显著标模拟。

### User Story 5 - 资料从输入到可引用资产 (Priority: P1)

来源 L2-B：事实资产不能持续归集与确认；L3：来源登记、原句定位、结构化建议、版本绑定人工确认。同族复用：新增车型说明、项目报道、服务资料、客户 FAQ 的同形态材料。

**Independent Test**: 内容运营登记链接并粘贴正文或导入 UTF-8 文本，查看原句支撑的建议，修改标签及可说/不可说，技术/项目/品牌分别确认，才进入可引用资产；更新后旧引用失效。

**Acceptance Scenarios**:
1. **FR-012** Given 内容运营登记标题、发布方、日期、链接或本地出处及正文，When 保存或导入文本，Then 产生待标注资料并去重；空输入、非法 URL、过大文件与伪装 PDF 均拒绝。登记链接不冒充已下载网页。
2. **FR-013** Given 待标注资料，When 请求建议，Then 展示来自原文的事实候选与字符位置，以及独立的产品状态/技术属性/项目阶段/客群字段；建议未确认不能当作可用事实，用户可纠正并保存审核版本。
3. **FR-014** Given 已标注版本，When 技术、项目、品牌各自确认，Then 仅记录本人职责签字；完整确认后来源可用；任何退回、编辑或新版本均不可继承旧确认。
4. **FR-015** Given 被稿件或传播关系引用的已确认资料，When 更新正文并保存新版本，Then 来源重新待确认，关联稿件当前签字与放行失效，关系标失效；新资料确认后须显式刷新稿件依据，不默默替换历史批准件。

### User Story 6 - 解释清楚传播关系，再交给 DRI (Priority: P1)

来源 L2-B：客户问题、能力、案例、主题尚无可解释关联；L3：白名单场景与能力匹配、证据片段回链、关系人工确认。同族复用：三类客群在同一申沃材料集中的场景选题。

**Independent Test**: 输入没有手选来源的新问题，得到场景/关注点、能力、来源及案例/非案例属性、主题与匹配理由；确认后在 DRI 需求池纳入。成本降幅无依据不造案例，陌生问题不硬套热门场景。

**Acceptance Scenarios**:
1. **FR-016** Given 不同客群的客户问题，When 执行规则模拟识别，Then 返回白名单场景及命中词、推荐能力、当前可用来源版本、原文/事实片段、案例阶段、传播主题、边界和图片建议；不得假称语义模型或匹配准确率。
2. **FR-017** Given 无成本测算、未确认来源或不相关问题，When 匹配，Then 明确缺什么、谁补证，不把产品页/合作/展会变成已运营案例；没有可靠证据不得确认成可宣传关系。
3. **FR-018** Given 有证据的建议，When 内容运营修改主题、选择证据并确认关系，Then 保留版本与人工理由，并进入 DRI 待排期；未确认关系不能被当成确认关系排期，重复确认/排期不重复建项。
4. **FR-019** Given 已确认传播关系，When DRI 纳入排期，Then 新稿件继承问题→场景→能力→来源/案例→主题及版本绑定，来源更新后禁止继续使用过期确认，刷新后数据/导出可回溯。

### Edge Cases

- 空问题、非法枚举、重复提交、双击审批不产生额外版本或重复记录。
- 未命中规则不等于事实已核实；正文自由文本不决定状态、角色或成熟度。
- 技术阶段、产品状态分别记录，不把辅助驾驶/合作/试点/量产/运营当作可自动升级的阶梯。
- 本地存储可被用户修改；本演示不宣称真实安全鉴权、不可篡改审计或企业签字。

## Requirements

### Functional Requirements

上面 FR-001 至 FR-019 即本次全部 AC。FR-001–011 对应 `tests/test_day1024_sol_roles.py`；FR-012–019 对应 `tests/test_day1024_sol_business.py` 的同名测试；不改变六题既有 AC。

### Key Entities

- Identity：六种演示角色与其责任白名单，不使用真实个人身份。
- Question：编号、模拟问题原话、客群、证据编号、来源反馈。
- Topic：编号、问题、负责人角色、周次、渠道、证据、图片、待确认项。
- Revision：稿件正文、内部备注、版本号、状态、当前版本审核与放行。
- Source / Picture：出处、日期、成熟度、使用边界与授权状态。
- Claim / Event / Feedback：历史批准口径、带角色/版本/时间的日志、模拟反馈。
- CollectedSource / Annotation：原文、出处、版本、事实候选及原文位置、独立状态标签、对外口径/边界、逐职能确认。
- CommunicationRelation：客户问题、场景枚举、能力、证据版本、案例阶段、主题、人工确认、过期状态。

## Success Criteria

- **SC-001** 六种身份可独立进入；每种身份至少一个职责专属操作；越权与跳审均被阻断。
- **SC-002** 一条可复现的客户问题到反馈闭环通过，同步覆盖四种渠道模板和缺证据阻断。
- **SC-003** 改稿失效旧签字、退回、重复动作三类反例均有自动化验证。
- **SC-004** 一份 HTML 离线打开无外链依赖；真实素材有出处，模拟数据和待确认状态显著可见。
- **SC-005** 保存/刷新/导出与窄屏检查通过。以上均为我方验收目标，不是业界实测或真实企业效果。
- **SC-006** 一条新增资料→建议→纠正→分职能确认→匹配→关系确认→DRI 排期路径走通，且用户不必手选来源才能启动匹配。
- **SC-007** 无测算成本、未知问题、来源改版、低可信候选四类反例有自动化证据；不把预置样例浏览计作持续归集。

## Assumptions

- 六种职能、流程、截止时间、问题和传播数字为演示设计，真实组织配置待企业确认。
- 使用用户指定素材及公开来源，不使用内部客户数据；图片只用于本地演示，未确认对外授权不得用于可放行稿。
- 只交付本地可点击窄切片，不做账号系统、服务端鉴权、模型调用、自动抓取、真实投放或公网部署。
- 新增资料登记与 UTF-8 文本导入是真实本地交互；抽取、标签与关系建议为确定性词表/模板模拟，非真实 AI 推理。PDF/DOCX/图片解析不支持，必须显式说明，不能把文件名当解析结果。
- 宪法技术栈规定面向生产原型；本次用户明确要求单 HTML mock，使用原生 HTML/CSS/JS，不改变生产架构。
- 用户未要求提交；先完成规格再写实现，但不代为 commit/push/PR。
