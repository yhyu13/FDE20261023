## 二、已安装的三个第三方 skill：能力边界

### 2.1 `ui-mockups`（S1，MIT，`.kilo/skills/ui-mockups/`）

**它解决什么**：把"平台"画成一张**看起来像真软件的截图**，而不是营销落地页。
核心方法三条：先定故事（一个工作区、2–4 个有名有姓的角色、一个正在进行的任务，全屏每个标签都指向同一件事）；由外而内搭（窗口外壳 → 工具栏 → 内容区 → 侧栏 → 浮层）；**自己截图回看**再交付。

可复用的硬规则（对本仓直接有效）：

| 规则 | 要点 |
|---|---|
| 发丝线代替阴影 | `1px solid #e6e6e2`；阴影只允许 `0 1px 2px rgba(20,20,15,.04), 0 8px 20px rgba(20,20,15,.05)` 这种"耳语级" |
| 一个强调色 | 状态色只用一个 accent + 绿=live/done，其余全是灰阶 |
| 界面文字 10–13px | 营销站字号出现在 UI 里 = 假的第一特征 |
| 密度即真实 | 真软件是 11px 标签、8px 间距 |
| 内容必须像真的 | 不许灰色占位块；骨架屏只能表示"加载中/进行中" |
| 图标 | 真实图标，不许裸 unicode 箭头/对勾（会变豆腐块或 emoji） |

附带 `references/components.md`：浏览器窗口外壳、含头像堆的工具栏、点阵画布、停靠侧栏、可漂移命名光标、"正在改…"徽章、流式揭示动画、flex 柱状图（无图表库）——全是可直接粘贴的内联片段。

> ⚠️ **本仓禁用项**：该文件的图标示例走远端热链（`icons.duckduckgo.com`、`api.iconify.design`）。咱们必须改成内联 SVG，否则离线打不开、也不符合可 diff 资产要求。

### 2.2 `web-prototype`（S2，Apache-2.0，`.kilo/skills/web-prototype/`）

**它解决什么**：**不从零写 CSS**。给一份已经编码好排版/间距/强调色预算的种子 `assets/template.html`（16.9 KB），再从 `references/layouts.md`（8 套现成 section 骨架）里挑、贴、填真实文案。

工作流：读种子 → 定 section 列表（**动手前先用一句话告诉用户选了哪几屏**，成本低、返工少）→ 贴骨架并把 `[REPLACE]` 换成真实文案（**填空就是选错 layout，别硬填**）→ 跑 `references/checklist.md` 自检 → 写文件。

自检表里与本仓红线直接撞上的几条：

- **No invented metrics**——页面上的每个数字必须来自用户/任务书，否则明确标成占位符（对应 AGENTS.md §13.3「不得宣称未验证的效果」）。
- **No filler copy**——不许 "Feature One / Lorem ipsum"（对应 §13.5「不做占位式交付」）。
- **Named real-world referents use the correct real images**——真名真物不能用生成物/仿制品替代；拿不到合规素材就保留并**明确披露局限**（对应本仓"⚠️ 待 Day1 现场确认"文化）。
- **No remote image dependencies**——所有用到的图要复制进工程并相对引用。
- 单一 accent 每屏最多出现两次；不许紫/藕渐变底；不许 emoji 当功能图标。

### 2.3 `html-artifacts`（S3，Apache-2.0，`.kilo/skills/html-artifacts/`）

**它解决什么**：**质量标杆库**。它带 20 个"完整可运行"的单文件 HTML 范例（来自 ThariqS/html-effectiveness，© Anthropic PBC，Apache-2.0，逐字原样捆绑，每个文件保留原版权头），外加一套 Claude 编辑部风格 house design system（象牙纸 `#FAF9F5` + 陶土色 `#D97757` + 衬线标题 + 等宽标签）。

与"平台 mock"最相关的四本参考：

| 文件 | 借鉴点 |
|---|---|
| `08-prototype-interaction.html` | 多屏可点击流程——**"手感"对不对**看这个 |
| `13-flowchart-diagram.html` | 带注释的流程图——**管线每一步点开看跑了什么、耗时、失败路径**，DevOps 味最足 |
| `11-status-report.html` | 周报式状态页——仪表盘/看板版式参考 |
| `18/19/20-editor-*.html` | 工单分诊板 / feature-flag 编辑器 / prompt 调参器——**"人在环里"的编辑器型界面**，且都以"导出"收尾（接口必须能把人做的决定带回真实流程） |

核心主张可以直接搬到咱们场景：**空间胜过线性**（有形状的东西要画出来）；**每个交互都要挣到自己的存在**（只为人的决策服务才加交互）；**必须有出口**（编辑器类界面结尾要有复制/导出，否则是死路）；**先扫后读**（先给 TL;DR / 数字，再展开）。

> ⚠️ **本仓需改**：`scripts/open-artifact.sh` 是 bash，Windows 跑不了；且默认输出目录 `~/.claude/artifacts/` 是 Claude 专属路径。咱们改成"直接落到 `assets/day1024/` + `Start-Process` 打开"。

## 四、内容侧：这种"AI 营销 DevOps 平台"到底该有哪些模块

以下是从 S10/S11/S13 交叉对齐出来的**模块地图**（行业通用概念，非本仓独创），用来反推 demo 的屏：

1. **口径库 / 知识库**：企业资料 + 品牌手册 + 标准名称术语 + 客户画像 + 历史优质内容 + 真实案例 + 禁用词与风险表达；**必须区分事实 / 说法 / 假设三类信息**。过期、下架、失效项不能继续被引用。
2. **素材库（DAM）**：AI 自动打标、语义检索、版本管理、有效期与版权联动、素材级细粒度权限、在线协同审批、全链路操作日志。
3. **合规前置检查**：文案规则检测（禁用词、必须附加的说明）、合作 ≠ 量产、驾驶辅助 ≠ 无人驾驶、不同车型能力不混用。
4. **选题与内容生成**：营销简报 → 检索品牌知识 → 多创意方向 → 渠道适配（公众号 / 官网 / 展会 / 销售推介）。
5. **人工审核与责任到人**：技术确认能力事实、项目确认进度、品牌确认表达；展示修改前后差异。
6. **复用与版本**：通过审核的表述存为口径，带出处/版本/适用范围；后续写稿直接调用，只审新增。
7. **效果回流**：内容表现、客户追问、新项目进展回到下一轮选题与补资料清单。

> 这些模块名与本仓 day1023 已有资产高度一致（`assets/day1023/result/submit/README.md` 的五步流程与口径库机制），所以这次不是从零发明，而是把"文字版方案"升级成"平台版 demo"。

## 六、[判断与建议]

以下是判断，不是已核实事实：

1. **优先用 `ui-mockups` 起手，`web-prototype` 做骨架，`html-artifacts` 只当参考库**。三个技能职责正交：一个是"画得像真平台"的审美与密度规则，一个是"别从零写 CSS"的工程法，一个是不动手也能先看的质量标杆。硬要用一个包打天下，最容易出的就是"紫色渐变 + 三层卡片 + 假指标"的通用 AI 味。
2. **demo 的可信度来自"每个数字有出处"，不来自"像素多好看"**。本仓审的是签字材料，视觉精致度排第二。宁可界面朴素，也要把"这条素材来自哪份文件、什么时间、什么阶段、谁确认过"做成一等公民。
3. **把 `⚠️ 待现场确认` 做成界面里的一个正式状态**，而不是脚注。这是本仓相对通用 demo 的差异化：让评审人一眼看出"哪里还没落地"，比假装全知更可信。
4. **`skills.sh` 注册表对这类"中文企业 demo"场景基本无效**，真正可用的是 GitHub 上做设计/原型的个人或小团队仓库。这类仓库的共同特征：质量门槛写得很细（清单、规则、自查），而这恰恰是能抄进 AGENTS.md 的部分。
5. **把 `mock-devops-platform` 这个自研 skill 当作唯一的入口**，别让下个会话直接去 load 三个第三方 skill 然后自己拼——拼法不一致正是"每次做的 demo 长得都不一样"的根因。
