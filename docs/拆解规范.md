# 拆解规范 · 三层结构与来源分级

> 本文件是六篇题解的**共同契约**。任何新增题目、改版题解都必须遵守。
> 目的：让六份方案在同一支团队手里可并行、可合并、可复用，并且**每一句话都站在可核对的证据上**。

---

## 一、三层拆解：L1 → L2 → L3

**只拆三层。不多不少。**

| 层 | 名称 | 判定标准 | 数量约束 |
|----|------|----------|----------|
| **L1** | 业务问题 | 现场大屏上的原题，一句话。**不拆。** | 1 个 |
| **L2** | 子问题 | L1 之所以发生的**能力缺口**，每条是一个可独立验证、独立交付的缺口 | **3–5 条** |
| **L3** | 机制 | 补上 L2 缺口的**可复用做法**（模型 / 规则 / 流程 / 数据模型四类之一） | 每个 L2 对应 **2–3 条** |

### 三条硬规矩

1. **L2 是缺口，不是症状。**
   "查手册慢"是症状（太浅，落到 L1 了）；"手册与工单没有可检索的结构化关联"才是缺口（可验证、可交付）。

2. **L3 必须是能复用的做法，不是功能名。**
   ❌ "做一个派工功能"（功能名）
   ✅ "技师技能画像 + 约束匹配打分 + 理由生成"（机制）
   判定法：把这个机制搬到另一个行业还成立吗？成立 → 是 L3；不成立 → 还没想透。

3. **不许出现第 4 层。**
   L3 里再出现的"怎么做"，属于**实现要点**，写进 L3 的说明列或"专项技术点"章节，**不再单独成层**。
   常见错误：L3 写成"OCR 识别 → 字段映射 → 归一化 → 校验 → 报表"——这是 5 步流水线，不是 5 个 L3。
   正确写法：L3 = "报价行结构化管线"（1 个机制），那 5 步是它的实现要点。

### 为什么是 3 层

| 层数 | 问题 |
|------|------|
| 1 层（只讲题目） | 没法干。听完不知道先做哪件事 |
| 2 层（问题→方案） | 中间缺了"为什么"，方案之间没有可比性，评审时无法判断优先级 |
| 3 层（L1/L2/L3） | 够用：L2 排优先级，L3 直接可转成技术任务与采购清单 |
| 4 层以上 | 变成流程图，不是拆解。现场讲不完，评审也排不出序 |

## 二、每篇题解的固定章节

```markdown
# 题 NN · <企业> | <原题>

## 〇、企业背景与选题校准      ← 联网查到的硬事实（带来源与等级）+ 对本题的校准
## 一、场景（L1 业务现场）      ← 现状 + 关键数字 + 数据在哪
## 二、三层拆解树               ← 核心章节
   ### L1 业务问题
   ### L2 子问题（表格：子问题 / 根因 / 为何值得做）
   ### L3 机制（表格：对应 L2 / 机制 / 怎么落地 / 同族复用）
## 三、项目定义与范围           ← 交付物 / 做与不做 / Echo-Delta 分工 / 成功标准
## 四、专项技术点               ← 三层技术栈：L1 技术域 / L2 组件 / L3 实现要点
## 五、OKR                      ← 1 个北极星 + 1 个护栏 + 支撑 KR
## 六、解决方案与架构           ← mermaid 架构图 + 关键链路 + 关键取舍
## 七、举一反三                 ← 本方案一并覆盖的同族问题（≤ 6 条）
## 八、风险兜底与 Day1 必问     ← 风险表 + 现场必问清单
```

**铁律**：L2 与 L3 的数量必须符合上表；`## 二` 与 `## 七` 不得省略——前者是拆解本体，后者是"举一反三"的落点。

## 三、举一反三的标注规则

每个 L3 机制后面必须带一列 **「同族复用」**，写清它**还能一并解决什么问题**。

判定标准（三条都满足才算同族问题）：

1. **同一类数据形态**（都是非结构化附件 / 都是时序数据 / 都是多约束分配）；
2. **同一类痛点**（都靠人工归集、都靠人脑记、都靠翻相册）；
3. **不需要换业务知识就能复用**（换的是数据，不换的是方法）。

反面例子（不算同族）："这个方案还能用于教育行业"——数据形态和痛点都变了，只是听起来宏大。

写法示范：

| L2 | L3 机制 | 怎么落地 | 同族复用 |
|----|---------|----------|----------|
| 多家报价无法横向比 | 报价行结构化管线 | 多格式解析 → 字段归一 → 源定位保留 | 投标文件符合性检查 · 多版本方案对比 · 供应商资质材料核验 · 集团内部结算 |

**由此推出的四条写作纪律**：

1. **不要写"XX 行业还没数字化"**——四家企业所在的四个行业**都已有平台或系统**。真空白永远更细：口径没归一、经验没结构化、数据停在个人手里、动作没闭环。
2. **不要写"业界准确率可达 XX%"**——没有权威测评就不要给数字。KR 里的目标值必须标注"**我们设定的验收目标（非业界实测）**"。
3. **能用国标/行标/官方口径当锚的地方，一定要锚**（GB/T 50500-2024、上海人社备案机制、新入职护士培训大纲）。锚了标准，方案就不是"我觉得"，而是"按规矩办"。
4. **⚠️ 但必须按行业条线选标准，选错等于全错。**
   山南勘测是**岩土工程勘察单位**，不是房建施工单位——
   判隐患要引**自然资源条线**（地质勘查/测绘）的判定标准，
   **不是**《房屋市政工程生产安全重大事故隐患判定标准》。
   **引错标准 = 结论在评审时直接无效。** 这是 2026-10-23 实跑题 05 时抓到的硬伤。

## 六、写给执行者的话

- **不要写"业界都用 XX 了"**——除非能给出可点开的来源；查不到就写"未检索到公开信息"。
- **不要写企业做不到的事**——例如"建议接入企业微信"前，先确认该企业是否用企业微信。
- **每个 L3 都要能回答"谁来做、多久、拿什么数据"**。答不上来的 L3 就是没拆透。
- **护栏指标不能省**。只报好看的指标，是这份交付物最容易被现场问倒的地方。
