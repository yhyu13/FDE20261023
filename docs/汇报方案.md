## 0，先说结论

- **六道题的官方口径我方题解有五道对得上，一道要改**：题 01 的报修对象（设备 vs 车辆）我方写死了车辆，已改成兼容写法，Day1 现场问一句定死。
- **三处我方题解漏了官方点名的要求**：题 02 的 KOL/KOC 与舆情管控、题 03 的 RAG 切片与召回缺陷、题 05 的"事后识别不要求速度"。这三处**照着官方口径补**，别按我方原来的范围裁剪讲。
- **今天下午的路演只讲一件事：这题我打算怎么做、Day2 交什么**。三层拆解和同族复用是加分项，不是主线。
- **讲解稿、网页、视频三件套已经齐了**，是路演候场和结项材料，不是路演主体。

## 2，今天下午 16:10 首轮方案路演

### 2.1 时间与形态

- 每题 **3 分钟**，六题 **18 分钟**，讲完接评委提问
- 讲的是**"我打算怎么做"**，不是"我已经做完了"——今天还没写一行原型代码
- 素材：`problems/NN-*-讲解稿.md`（我念稿子）+ 讲解稿的**分层拆解树**（投影）+ `overview.html` 的对应小节（备用）

### 2.2 每题 3 分钟怎么排

| 时间 | 讲什么 | 不讲什么 |
|------|--------|---------|
| 0:00–0:30 | **这题的真问题**（官方口径那句 + 我方查到的一句企业事实） | 背景铺垫、题面复述 |
| 0:30–1:30 | **L2 的 2–3 条能力缺口**（只讲最要命的 2–3 条，不是全部 4 条） | 逐条念 L2 |
| 1:30–2:30 | **L3 机制怎么落地**（选 1 条最能打的，讲清它怎么把那条缺口补上） | 全部 11–13 条机制 |
| 2:30–3:00 | **Day2 交什么 + 怎么验**（具体到能演示的一个切片） | 完整方案、ROI 测算 |

### 2.3 六题的一句话主张

| 题 | 一句话主张（路演第一句就说这个） |
|---|---|
| 01 | 老师傅的排查顺序没进系统，我们把它变成**能检索、能派工、能带新人的条目** |
| 02 | 智能驾驶的内容不是"写几篇稿子"，是**素材可检索、事实有出处、投放和舆情接得上**的一套流水线 |
| 03 | 蓝莓的问题定位卡在 RAG 的切片和召回上，**按业务对象切、按混合召回取**，才谈得上溯源 |
| 04 | 报价比选的真风险是**口径和单位**，我们让每个数字都能点回原件、都能人工点头 |
| 05 | 照片归档要落到**孔号、工序、部位**三个维度，**新人拿着判据卡也能判** |
| 06 | 排课不该交给大模型硬排，**规则保合法、求解保最优、人工保可解释** |

## 3，明天（10/24）下午 15:15 原型路演与专家质询

### 3.1 每题只演示一个切片

| 题 | 演示什么 | 怎么验 | 备用的降级版本 |
|---|---------|--------|--------------|
| 01 | 输入一条模拟报修 → 出候选原因 Top-3 + 排查步骤 + 建议派工，每条带出处 | 拿历史闭环工单回测，出一张命中率表 | 只做经验条目检索（不接工单） |
| 02 | 一批素材 → 场景打标 → 出三平台初稿 + 参数溯源标记 + 合规拦截演示 | 塞一条错误参数，看它能不能拦住 | 只做"素材→初稿"单链路 |
| 03 | 问一句"这批果子的糖度为什么低" → 定位到可疑环节，列出依据 | 人工标 20 条，看命中几条 | 只做标准条款→可勾选作业项 |
| 04 | 丢三份格式不同的报价 → 归一后出比选台账，每格能点回原件 | 灌一份有漏项的，看能不能抓出来 | 只做单份解析 + 字段归一 |
| 05 | 丢 200 张现场照 → 出隐患候选 + 孔号索引 + 判据卡 | 出召回/精确率表 + 混淆样本图 | 只做孔号 OCR + 照片合规检查 |
| 06 | 给花名册 + 约束 → 出跨月名单与排课，换 2 个人后重排 | 断言硬约束零违反 + 可解释理由 | 只做分层抽选（不排课） |

> **降级版本很重要。** 明天现场时间紧，某个模块没跑通时，能立刻退到窄切片，仍然能讲清一个闭环。

### 3.2 专家质询最可能被问到的问题（提前准备答案）

| 会被问 | 怎么答 |
|--------|--------|
| 准确率多少 | 说清是**我方验收目标还是业界实测**。没有权威独立测评的，只给目标值和基线自建计划，不给"业界可达 XX%" |
| 数据从哪来 | 主办方**后续提供模拟数据**；真实数据在客户现场、当场、经授权使用，不入库不出厂区 |
| 这跟现成 SaaS 有什么区别 | 讲**可溯源**（数字能点回原件）和**口径归一**这两件现有 SaaS 不做的事 |
| 大模型编错了怎么办 | 低置信走**人工确认台**，未确认的不进主表、不发布、不作为证据 |
| 多久能上线 | 分**演示闭环**与**生产上线**两段说，别混 |

## 4，后天（10/25）项目验收与结项打卡

交三样，对应官方口径的"实战收获"：

- **真实卡顿**：每题记 2 次实际踩坑（数据格式、口径、模型失败样本），这是官方点名的第一项
- **团队 AI 模型**：带评测集和回测脚本的模型，不是"我们接了 XX 大模型"
- **测试与验证记录**：甲方人工抽检表 + 断言报告 + 干预重排演示记录

外加：`specs/NNN-*/spec.md`（验收标准的真源）、`pr/NNN-*.md`（每题一份 PR 描述，填了"动了哪条 AC / 测试证据 / 闸结果 / 没做什么"）、`overview.html` 与六个讲解视频。

## 5，风险与待确认

### 5.1 今天下午必须问清的

1. **题 01 的报修对象是设备还是车**（决定字段名、备件体系、派工池）
2. **题 02 第一轮做不做舆情与调性**（官方点名了，我方原方案划在范围外）
3. **题 03 的 RAG 期望是切片粒度还是召回策略**（命题方点了两处缺陷）
4. **模拟数据的形态与规模**（主办方后续提供，什么时候给、什么格式）
5. **各题的验收人与签字口径**（谁签字、什么算过）

### 5.2 六题最大的技术风险

| 题 | 最大风险 | 现在的退路 |
|---|---------|-----------|
| 01 | 老师傅不配合录经验 | 语音录入 + AI 代拟，只让他确认；范围砍到 Top20 高频 |
| 02 | 做成通用文案机，市场部说"我自己也能写" | 全程用市场部自己的真实选题与素材；做参数溯源与合规拦截这类他们自己做不到的 |
| 03 | RAG 召回不达标（命题方已点명） | 业务对象切片 + 混合召回；退到标准条款→可勾选作业项这一层先跑通 |
| 04 | 口径规则拿不到 | Day1 硬性要求；拿不到就退到"格式归一 + 源定位"，不产正式台账 |
| 05 | 误报高，安全员失去信任 | 先只对高置信 + 明确条目出结论，其余只做检索不报警 |
| 06 | 约束违反或不可解释，医院不认 | 求解器出名单 + 逐条理由；模型只做规则抽取，不参与决策 |
