## 2. 常用命令

```powershell
# —— 闸 ——
python tools/run_all_gates.py              # 全套（看退出码，不看输出文本）
python tools/run_all_gates.py --list       # 只列
python tools/run_all_gates.py --only test,lint

# —— 开一棵工作树（并行就开树，不在同棵树上打架）——
python tools/new_worktree.py -Feature 1 -ShortName repair-copilot
python tools/new_worktree.py -Feature 1 -ShortName repair-copilot --DryRun
python tools/new_worktree.py --List

# —— 从题解生成 spec ——
python tools/seed_spec.py -Number 1 -ShortName repair-copilot

# —— 日常 ——
uv run --group dev pytest                 # 测试
uv run --group dev ruff check .           # lint
git worktree list                          # 我在哪棵树上？
```

## 3. spec-kit 命令（在 Mavis 里用）

| 命令 | 什么时候用 | 产出 |
|------|-----------|------|
| `/speckit.constitution` | 改仓库原则 | `.specify/memory/constitution.md`（**已写好，别动**） |
| `/speckit.specify` | 新功能 | `specs/NNN-slug/spec.md` |
| `/speckit.plan` | 规格定完 | `specs/NNN-slug/plan.md` |
| `/speckit.tasks` | 方案定完 | `specs/NNN-slug/tasks.md` |
| `/speckit.implement` | 任务就绪 | 代码（每个任务走 TDD） |
| `/speckit.clarify` | 规格里有歧义 | 澄清后的 spec |
| `/speckit.analyze` | tasks 之后、implement 之前 | 跨产物一致性报告 |
| `/speckit.checklist` | 想要需求完备性清单 | `checklists/` |
| `/speckit.taskstoissues` | 任务要分出去 | GitHub issues |
| `/speckit.converge` | 回扫代码库补任务 | tasks.md 追加 |

> 六道题**不用**从零跑 `/speckit.specify`——`tools/seed_spec.py` 已经把 80% 搬好了。

## 4. 三条最容易出事的地方

| 坑 | 症状 | 防线 |
|----|------|------|
| **两个会话在同一棵工作树** | 分支被换掉、HEAD 被抽走、无头浏览器抢 CPU、两边改同一批文件 | 一树一会话；动手前看三眼（`branch --show-current` / `reflog` / `status`） |
| **把「没跑」写成「通过了」** | 闸报绿，但什么都没查 | SKIP 与 OK 分开；空跑（checked=0）转红 |
| **模型编事实 / 算错数** | 台账数字对不上、对外口径出事 | 溯源强制；算术走代码；低置信走人工确认台 |
